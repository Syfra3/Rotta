## Offline Pi history reader (not wired to live telemetry)

`pi_history.read_history(session, checkpoint, sink)` accepts only explicitly supplied paths; it never discovers or opens the Pi HOME/session directory by itself. It parses complete newline-terminated Pi v3 session JSONL records (installed Pi 1.4.0 `docs/session-format.md`), emits bounded `tool_result` status metadata and one `derived` session record per unique complete header (hashed ID) to an owned local JSONL sink, and checkpoints the byte offset, prefix digest and header digest. Raw IDs, content, arguments and paths are never persisted in the sink or checkpoint. The sink is the idempotent delivery boundary: a restart after sink fsync but before checkpoint replacement replays without duplicate keys. Partial input lines wait for completion within the 1 MiB per-line bound; oversized unterminated lines, unknown Pi entry types, a rewritten/truncated session, unsupported header, or exceeded 10,000-record limit fail closed and requires operator inspection/reset. The sink and checkpoint are mode 0600. This prototype is **not** connected to the collector, does not emit logs/traces or publish its derived session records as a live durable-session count, and does not read actual Pi history; do not mistake sink records for live Pi or Grafana signals. A torn sink write or concurrent writers require explicit recovery; no automatic repair or global exactly-once guarantee is claimed. Run `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s observability -p test_pi_history.py` on synthetic temporary files only. Next integration must define a bounded local metadata transport and atomic single-writer ownership before any opt-in real-history operation.

## OpenCode telemetry (opt-in)

**Source update, not yet activated:** the adapter filters the server-wide event
stream by location and workspace, accepts complete reported usage on failed steps,
and retries failed or rejected posts while loaded. Events without a matching location
are ignored. Metadata includes bounded model/agent, completed tool outcomes, run
outcomes, observed new main/child sessions and compaction reason. Model identifiers
are retained locally and may reveal private names. Unknown agents are `unknown`;
tool names that are not confirmed builtins are `unknown`, not assumed MCP. Code
Mode can hide individual MCP calls. New-session counts do not reconstruct existing
sessions; a parent relationship does not prove a particular agent role. Correlation
maps and delivery queues are bounded and volatile; starts missed before plugin load,
evictions, reloads and shutdown may lose attribution or samples. `increase()` panels
need enough scrapes and can extrapolate. Prometheus retains data seven days and the
collector expires inactive metrics after five minutes. These changes have synthetic
event tests and a disposable real-collector test, not live OpenCode end-to-end proof.
The optional dashboard is `/d/ai-cli-opencode`; a bind-mounted Grafana can reload
dashboard files automatically even before the collector and plugin are upgraded.
Old OpenCode counters may already contain duplicates and are not repaired.

An unchanged owned plugin can now be upgraded by the installer after stack identity
checks. Upgrade stores `.rotta-telemetry-plugin.bak` and a journal until completion;
if either remains after interruption, stop and inspect them and the ownership receipt
before recovery. No automatic history deletion or stack restart is performed. The
new collector config must also be loaded separately for the new metrics.

`opencode-telemetry.mjs` is installed as a user-wide plugin only on explicit OpenCode telemetry opt-in. The v2 wrapper accepts matching-location `session.step.ended` and `session.step.failed` events with complete usage and passes them through the portable completed-message adapter, which requires nonnegative safe-integer token values for all four categories and optional finite nonnegative estimated USD cost. Missing usage is absent, never zero. It POSTs content-free OTLP metrics only to `127.0.0.1:14318`, without any IDs, prompts, paths or tool contents. The local Prometheus metrics store retains samples for seven days; Rotta has no remote upload. The exporter sends process-local cumulative monotonic OTLP Sum points (temporality 2), with one process start time, strictly increasing point timestamps and serialized sends. Backpressure retains at most one in-flight export body and one pending latest cumulative snapshot; intermediate snapshots are coalesced. Failed posts and HTTP errors are retried while loaded, retaining the latest cumulative snapshot. Shutdown loses pending in-memory data. Known cost remains present in subsequent snapshots even when a message has no cost. Duplicate completed message IDs are suppressed within the current instance (1024 most recent IDs); eviction, plugin restart or replay can recount old messages. A collector HTTP acceptance does not guarantee durable delivery. Do not interpret these best-effort counters as billing or exactly-once totals.

OpenCode v2.2.7 loads a default definition from the managed plugin directory. The version-matched binary previously loaded the adapter in an isolated runtime; the new event mapping and location filter have not been tested against real provider events. `python3 observability/install.py install --host opencode` installs or upgrades the owned plugin at `~/.config/opencode/plugins/rotta-telemetry/server.js` and updates its independent hash receipt; it does not touch Pi settings. `status --host opencode` reports ownership, and `uninstall --host opencode` removes only the unchanged owned directory and receipt, retaining the shared stack and volumes. A modified or unowned directory, extra file, legacy artifact, interrupted journal or leftover upgrade backup requires inspection. OpenCode watches plugin files; `/reload` can force configuration reload if necessary. Historical usage is not reconstructed; synthetic OpenCode zero is not native usage.
